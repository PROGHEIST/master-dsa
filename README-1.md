# DSA Interview Preparation Roadmap

A practical, interview-focused Data Structures and Algorithms (DSA) syllabus for students preparing for software developer and full-stack developer interviews.

> **Goal:** Build problem-solving confidence and learn the DSA concepts most commonly used in coding interviews. You do not need to master every advanced algorithm or become a competitive programmer.

## How to Use This Roadmap

1. Choose one programming language and use it consistently.
2. Learn the concept before attempting problems.
3. Solve problems yourself before looking at solutions.
4. Explain your approach and its time and space complexity.
5. Revisit problems you could not solve independently.

Suggested daily study time: **1–1.5 hours**.

## 30-Day Study Plan

| Days | Topics |
|---|---|
| 1–3 | Time and Space Complexity, Arrays |
| 4–6 | Strings, Hashing |
| 7–9 | Searching, Sorting |
| 10–12 | Two Pointers, Sliding Window |
| 13–15 | Linked Lists |
| 16–17 | Stack, Queue |
| 18–20 | Recursion |
| 21–23 | Trees, BST |
| 24–25 | Heap, Graph basics |
| 26–27 | Greedy, Dynamic Programming basics |
| 28–30 | Revision, mixed problems, mock interviews |

The schedule is flexible. Spend extra days on topics that you find difficult rather than rushing through the syllabus.

## Practice Targets

Aim for approximately **55–60 carefully selected problems**.

| Difficulty | Target |
|---|---:|
| Easy | 35 |
| Medium | 20 |
| Hard | 0–5 |
| **Total** | **55–60** |

Prioritize understanding the solution and recognizing the problem-solving pattern. Do not memorize code without understanding it.

## Interview Preparation Tips

DSA is only one part of a software developer interview. Alongside this roadmap, revise:

- Object-Oriented Programming (OOP)
- DBMS and SQL
- Operating Systems fundamentals
- Computer Networks fundamentals
- Your programming language fundamentals
- Your projects, architecture, and technical decisions
- Role-specific skills such as JavaScript, React, Angular, Python, Django, or REST APIs

For every coding problem, practice explaining:

1. What is the problem asking?
2. What is the straightforward approach?
3. Can you optimize it?
4. What is the time complexity?
5. What is the space complexity?
6. Have you considered edge cases?
